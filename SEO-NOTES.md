# SEO notes: xgrcsoftware.com

Working notes for the SEO Fix Spec (29 Sept 2026). Step 0 findings first, then decisions per task.

## Step 0: how the site is built

The site is **not WordPress**. It is a static [Astro](https://astro.build) site in this repo. `npm run build` writes `dist/`, and nginx on the same VM serves `dist/` directly, with Cloudflare in front. The `/wp-content/`, `/wp-includes/` and Gravity Forms paths Google still sees are left over from the old WordPress site (replaced July 2026). Today they return 200 with the homepage because of the fallback described below.

Running `npm run build` in `/opt/www/XGRC_WEBSITE` **is** a production deploy: nginx serves that `dist/` folder live, and the postbuild step pings IndexNow.

## How Priority 1 changes the setup

The nginx vhost now lives in the repo so it can be reviewed in a PR:

- `deploy/nginx/xgrcsoftware.conf`: the full production vhost (copied from `/etc/nginx/sites-enabled/xgrcsoftware` on 29 Sept 2026, then changed).
- `deploy/nginx/redirects.conf`: **the single redirect map.** It replaces `docs/domain-cutover-redirects.conf` and also holds every redirect that used to sit in the vhost, except http to https and www to apex (whole-host redirects that must stay in their own server blocks).
- `scripts/check-redirects.mjs`: fails the check if any redirect target is itself redirected (a chain), is missing from the build, or lacks a trailing slash.

Merging the PR changes nothing live. The deploy steps are under "Manual changes".

## Manual changes (outside the repo)

Deneys must approve these before they run. They go in this order, straight after the PR is merged into `main` and pulled into `/opt/www/XGRC_WEBSITE`:

1. `cd /opt/www/XGRC_WEBSITE && CI=true timeout 600 npm run build` (builds the new `404.html` and sitemap; this is the site deploy).
2. `sudo cp /etc/nginx/sites-enabled/xgrcsoftware /etc/nginx/xgrcsoftware.bak-<date>` (backup).
3. `sudo install -m 644 deploy/nginx/xgrcsoftware.conf /etc/nginx/sites-enabled/xgrcsoftware`
4. `sudo nginx -t && sudo systemctl reload nginx`. If `nginx -t` fails, restore the backup and stop.
5. Purge the Cloudflare cache (Caching > Configuration > Purge Everything), so no cached homepage copies are left on unknown URLs.
6. Run `BASE=https://xgrcsoftware.com ./scripts/seo-check.sh`.

Between the merge and step 4, the old live vhost still includes `docs/domain-cutover-redirects.conf`, which the PR removes. nginx keeps running on its loaded config, but an `nginx -t` or reload in that window (for example a certbot renewal) would fail. Do steps 1 to 4 together.

## Decisions and findings per task

### T1: real 404s
- New `src/pages/404.astro` builds `dist/404.html`: noindex, links to Home, Solutions, Insights and Contact.
- Vhost fallback becomes `try_files $uri $uri/ =404;` with `error_page 404 /404.html;`.
- Impact check: I compared every URL with impressions in GSC (27 Jun to 26 Sep 2026, 414 URLs) against the build and the redirect map. Only 4 would change from a soft 200 to a 404. Three now get redirects (see T2). The fourth, `/wp-content/plugins/ubermenu2/`, is meant to 404.

### T3: trailing slashes
- Every internal link now ends in a slash. That was about 180 links in the nav, footer, templates and article bodies (`src/data/articleContent.js`). Links to files (.pdf, .md) are unchanged.
- Only `href` values changed on `/contact/` and `/login/`. The forms were not touched.
- `node scripts/seo-build-check.mjs dist` crawls the build. It fails on any internal link without a slash, any link to a redirect, and any link to a missing page.

### T4: SearchAction
- The current site has no SearchAction. `orgSchema` in `Base.astro` has Organization and WebSite only. The `/?s={search_term_string}` URL Google keeps trying came from the old WordPress (Rank Math) schema. Google will stop trying it once it recrawls. `/?s=...` now serves the homepage, because nginx ignores query strings.

### T5: .md files
- The vhost's `.md` location sends `Link: <https://xgrcsoftware.com/<page>/>; rel="canonical"`. A `.md` with no matching page gets `X-Robots-Tag: noindex` instead. Today all 98 have a page, which the build check confirms.
- The staging host `xgrcwebsite.nucleusapps.online` still uses `docs/nginx-md-headers.conf`, so its server-wide noindex keeps applying.

### T6: sitemap
- The sitemap lists 136 URLs, which is every indexable page. Each one is built, self-canonical and not noindex (the build check enforces this). Redirects, `/login/`, `/preview/`, `/tour/*.html` and `.md` files are left out.
- `lastmod` comes from `src/integrations/sitemap-lastmod.mjs`. It hashes each page's `<main>` content and changes the date only when that content changes, so a slash-only link change does not count. The ledger is `.seo-lastmod.json` (not committed). On the first production build, dates are seeded from the article date, or from the source file's last git commit.
- The two landing pages submitted to GSC as sitemaps must be removed there by hand (see Manual changes).

### T7: use-case pages
- Product pages now have a "Related use cases" block, built from `relatedSolution` in `src/data/useCaseRegistry.js`.
- `/solutions/` has a "Use cases by solution" section.
- The ISO and regulatory use cases link up to their hub pages.
- The two hub pages, `/use-cases/iso-compliance/` and `/use-cases/regulatory-compliance/`, were thin (381 and 236 words, and one had no FAQ). Both now have at least 900 words, South African legislation, a FAQ and FAQPage schema.
- All 35 use-case pages have at least 3 internal links pointing to them, at least 600 words, a South African regulation reference and a FAQ.
- Libryo, Hakware and XRM have no use cases in the registry, so their product pages show no block.

### T8: noindex settings
- `/products/vcm/` **does not exist on the current site.** Today it returns the homepage with a 200 (the soft 404). The noindex GSC reports must date from the old WordPress page. After T1 it returns a real 404. Nothing is set on purpose here. **Deneys to confirm:** should vendor compliance get an indexable page (T14 would link to it), or should `/products/vcm/` 301 to `/compliance-hub/`?
- `/wp-content/plugins/*` and `/my-account/` do not exist either. After T1 they return 404, which is correct.
- `/tag/*` has no pages and no redirects, so after T1 it returns 404. `/category/*` and `/author/*` 301 to `/insights/` (see T2). There are no paginated archive pages on the new site.
- `/login/` is the only noindex page, and that is intentional.
